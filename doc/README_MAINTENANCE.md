# README 与版本历史维护规则

2026-10-28 确定：后续 Release 沿用本次文档组织方式。

## 中英文介绍

- 根目录 `README.md` 是默认中文介绍，也是内容与版式的基准。
- `README.en.md` 与中文并列，顶部放置互相切换的语言链接。
- 先核对用户最新修改的中文正文和图片，再同步英文的文案、章节顺序、评价、链接和截图版本；保留用户已经确认的内容。
- 图片在 `doc/images/readme/` 共用，不为英文版另复制一套；截图更新后两种语言同时生效。
- 介绍围绕小、快、简洁、所见即所得与丰富的表格编辑等具体使用体验展开。尺寸、性能、版本与功能说明以对应实际程序为准。

## README 的内容顺序

软件介绍与下载、主要功能、背景、软件截图与配色、演示入口、后续开发计划、版本历史入口、反馈、用户评价、Star 历史、文档说明、感谢支持。

背景紧随主要功能，沿用作者本人的口吻。用户评价保留真实内容、用户名与对应回复链接；英文翻译注明译自中文。赞助者保留已确认的脱敏姓名与留言，不列金额。

## 版本历史与计划

- 最近版本的详细更新、已知问题与当时的验证说明写入 `doc/CHANGELOG.md`，最新的在前。
- README 保持稳定的下载与历史入口，不再逐版堆叠更新详情、测试数字和交付日志。
- 发布前同时核对公开仓库与本地版本历史，不能用较旧的本地文件覆盖较新的公开记录。
- 旧正文需要整理时先留档，再迁移；保留曾经公开的历史，不静默丢弃。
- README 保留后续开发计划，公开的版本安排集中在 `doc/PUBLIC_ROADMAP.md`。本地开发队列与内部验收记录另行维护。

## 演示与截图

- `demo/` 是长期演示素材目录，开场为「你好，沙枣」，核心文案为「从一行文字，到一份作品」。
- 截图展示实际程序的阅读、编辑、图表、公式、表格、代码与外观特点，覆盖浅色、深色和其他预设配色。
- 用户替换的截图优先保留。同步截图说明中的程序版本，并更新演示目录的记录；旧拍摄的程序哈希不能冒充新截图的程序身份。
- 不拼造软件功能，不把候选截图或静态检查当作正式版本的完整验收。

## 文档发布

1. 从公开仓库当前分支创建独立的文档发布副本，避免把开发源码和无关改动带入分发仓库。
2. 按文件清单发布中英文 README、版本历史、公开计划与说明、引用的图片和演示文档。源码、个人设置、私有测试资料与缓存不在这份文档清单内。
3. 检查中英文的章节和图片对应、所有新增公开文档的本地链接、图片可读性、用户评价来源，以及 Star 历史图。
4. 核对具体改动后提交、正常推送；远端有新提交时先重新核对，不强制覆盖。
5. 发布后匿名读取公开页面与文件，确认 README 默认中文、英文切换可用、图片和演示文档齐全、changelog 最新记录正确，并核对发布文件的字节或 SHA-256。
6. 单独更新文档时不创建程序版本或改动既有 Release 附件。完整程序 Release 继续执行项目规定的构建、验证、发布和双目录归档流程。
